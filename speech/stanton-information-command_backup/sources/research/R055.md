K NOWLEDGE R ETENTION T EST (KR-T EST )
The Knowledge Retention Test (KR-Test) is a corpus-specific factual evaluation benchmark designed to measure whether a model retains fine-grained knowledge from a training dataset after
retraining or unlearning interventions. A detailed description of the benchmark is provided in our
accompanying preprint [? ]; here we summarize its construction and evaluation protocol.
KR-Test is constructed from the Wikitext corpus. Each example consists of:
1. A short context extracted from a paragraph,
2. A factually correct completion consistent with the source article,
3. A factually incorrect completion that differs minimally from the correct one.
The false completion is designed to be syntactically similar and semantically plausible while violating a key factual constraint. We avoid trivial surface cues (e.g., simple negation without factual
modification) and discourage purely date-only substitutions where possible. Both completions are
intended to appear equally fluent.
G ENERATION M ETHODOLOGY AND VALIDATION
KR-Test can be LLM-generated or human-annotated. We construct examples automatically from
source corpora using gpt-4o-mini with a constrained prompt that enforces (i) short contexts, (ii) two
fluent continuations, and (iii) minimal surface-form differences between the true and false completions while altering key factual content. Concretely, for each source passage, we request the model to
output two entries in a structured JSON format containing context, sentence true, and sentence false
(with a placeholder location field), and we parse only valid JSON outputs.
Source extraction. For Wikitext, we first segment articles into multi-sentence passages by scanning the training split and aggregating consecutive lines until the next section header boundary. We
discard very short segments (fewer than 10 lines) to ensure sufficient factual content for constructing
non-trivial discriminations. We then sample passages and query a frontier model via API to generate
two KR-Test items per passage. (The full prompt and code used to extract passages and generate
entries is included in our released scripts.)
False continuation construction. Incorrect statements are created by gpt-4o-mini via minimal
factual perturbations of the correct continuation. The prompt explicitly requests that the true and
false continuations remain nearly identical in sentence structure and fluency, differing primarily in
a small number of factual keywords (e.g., entities, relations, attributes). In addition, we instruct the
generator to avoid low-quality negatives such as trivial date-only substitutions when possible, and
to avoid placing answer-revealing cues in the context.
Validation and filtering. We apply lightweight automatic validation to ensure formatting and consistency: (i) strict JSON parsing; (ii) presence of required fields; and (iii) non-empty strings for
context, sentence true, and sentence false. Samples failing any check are discarded. In addition to
structural checks, we verify that the false continuation differs from the true continuation in at least
one key factual token and that both options remain fluently formed. We further manually audited a
random subset of 200 samples to confirm factual contradiction and fluency matching.. Representative examples across difficulty levels are shown in Table S2.
In addition, we manually spot-checked a random subset of generated items to verify that false continuations contradict the source passage and that the two options remain matched in fluency.
Difficulty distribution. We stratify KR-Test examples into easy, medium, and hard categories
based on the type of factual manipulation (semantic contradiction; single-attribute perturbation; relational/institutional or mechanistic perturbations). We report representative examples per category
(Table S2); we leave a full distributional breakdown as future work, since difficulty binning requires
either additional automated heuristics or human adjudication.

setting underscores its broad applicability.

Our intuition mirrors that of the LLM experiments: we aim to prevent the model from overfitting
to high-probability modes while preserving low-probability, diverse samples. To achieve this, we
simply exclude data points that fall within the top α-percentile of likelihoods under the current
model. In our experiments (Figure S2), we set γ = 0.8.
To simulate recursive data generation in a non-neural setting, we adapt our filtering strategy to Gaussian Mixture Models. Algorithm S1 describes the procedure: starting from an initial dataset, a GMM
is repeatedly fit to the current data and used to sample new points. At each iteration, we compute
the likelihood of each sampled point under the fitted model and discard the highest-probability samples, retaining only those below the γ-percentile threshold. This ensures that subsequent datasets
remain diverse and are not dominated by a small set of high-likelihood modes, thereby mirroring the
mitigation strategy applied in our language model experiments.
