So — how did we get all of this?

The collection architecture is a fourteen-layer automated pipeline. Each layer builds on the one before it.

It starts with domain discovery — finding each contractor's internet presence from a company name and an address. An AI research layer then validates those domains by cross-referencing web sources. It traces acquisitions, identifies mergers, and corrected nine hundred eighty-seven domains where the initial lookup was wrong.

Domain verification fetches each homepage, checks the SSL certificate, looks for the contractor's name in the page content, and flags parking pages. DNS intelligence pulls MX, SPF, DMARC, and nameserver records — identifying email providers and, critically, whether DMARC is deployed.

Certificate transparency queries crt.sh for every TLS certificate ever issued against the domain. That gives us subdomains — VPN portals, authentication servers, internal applications — mapped from public certificate records.

Web fingerprinting identifies server software, content management systems, and security headers. Shodan queries find internet-facing hosts, first by organization name, then by individual IP. Per-IP enrichment returns service banners — product names, version numbers, SSL certificates, and known vulnerabilities.

ASN enumeration establishes who owns each IP address. On-premises classification separates contractor-controlled infrastructure from cloud providers. Service risk classification cross-references exposed ports against actual Shodan banners — if the banner says OpenSSH on a database port, the system labels it as SSH, not as a database.

NVD scoring grades every vulnerability by severity. And the final layer extracts named entities from each contractor's intelligence brief and builds them into a knowledge graph.
