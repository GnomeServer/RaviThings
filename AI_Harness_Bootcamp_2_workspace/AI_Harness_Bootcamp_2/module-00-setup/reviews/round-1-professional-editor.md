## Making-of findings

1. PUBLIC_RUBRIC.md:7 — 'A working environment is the entry condition for the session. It is not part of the result and is not scored here.' This is pure scoping rationale: it explains what the course chose to put inside the assessment boundary and what it left out. A mentor handing over the same standard would say what is measured; they would not explain what was excluded and why. Direct F2 hit and an X5 candidate.
2. PUBLIC_RUBRIC.md:3 — 'This is the standard your work is measured against, and you can read all of it before you start.' The clause after the comma is the document describing its own publication policy. The design decision to publish the rubric is builder-facing; the learner needs the rubric, not the reasoning for its availability.
3. README.md:3 — 'Plan for 1–3 hours of machine setup, then one three-hour class session.' Scheduling. The setup duration survives outside a course (a person budgeting an afternoon); 'one three-hour class session' does not exist without the artifact.
4. README.md:44 — 'Setup runs in the same ten stages on every platform:' followed by a ten-item list. This is the document explaining its own structure across sibling documents — 'this document is organized as'. Each guide numbers its own steps; the learner reads exactly one guide and never needs the cross-platform symmetry.
5. MODULE_00_LAB.md:9-24 — the 'Timebox' table itemizing eleven parts of a session in minutes. Session structure and scaffolding. A per-task time limit taught as craft ('stop after twenty minutes and reassess') survives outside a course; a schedule of an event does not.
6. MODULE_00_LAB.md:304 — 'Passing the practice check does not pass the module.' The real lesson underneath (a local check is not the acceptance authority) is stated correctly elsewhere; this clause states it in course-registrar terms instead.

Borderline but I flag it: this is a description of the assessment architecture rather than a craft rule. ## Sentences that read as generated

1. README.md:79 — 'A tool saying “done” is not the same as a file on disk. A version string is not the same as an authenticated write. The checks make those differences visible.' Two identically-shaped 'X is not the same as Y' clauses in sequence, then a third sentence whose only job is to point at the first two. The tell is that the third sentence adds no information; it exists to close the cadence.
2. NEXT_MODULE.md:9 — 'A tool reporting "done" is not a file on disk, and a fluent sentence is not a verified one.' 3. MODULE_00_LAB.md:304 — 'Passing the practice check does not pass the module, and failing it is evidence, not a verdict.' Two antitheses stacked; the second is an aphorism that repeats what the preceding four sentences already told the learner to do.

## Verdict

FAIL against §6 Class F. 24/32 from this seat; acceptance requires 32/32 from every reviewer, so this does not pass, and one editor's 24 is by itself disqualifying regardless of what the other two seats return. Separately, F2 fails outright and X5 is triggered: at least eleven learner-facing sentences explain how the course is scoped, scheduled, staffed, or assessed, with PUBLIC_RUBRIC.md:7 and README.md:44 the least defensible. The prose is far above the field baseline the Reference cites — it is exact, it never hypes, it treats failure properly, and TROUBLESHOOTING.md in particular reads like someone who has sat with a stuck beginner. What holds it back is three fixable classes of defect: an epigram habit that gives every fourth paragraph the same closing cadence (dimension 8), one idea summarized in four places plus a whole recap file (dimension 6), and a set of inspection steps that ask the learner to confirm rather than to read a value back (Degani guideline #1, and the module's own §4.4 rule that a verification response portrays the value). Two things I want the human editor in this seat to look at first, because they are defects of fact rather than taste: windows-powershell.md:22, which cannot be read aloud and does not tell the learner what value to look for; and windows-wsl.md:357, where a pasted block fabricates the very observation the following "You should see" line then accepts. Also worth a pass: the five guides define PATH five different ways ("directories your shell searches" / "folders your shell searches" / "folders your terminal searches" / "folders Windows searches"), which is an F1 problem as well as a one-voice problem, and the heading "Repeat the proof in a fresh shell" appears in all five guides over the module's longest and most consequential section, which does far more than repeat.
