## Capability and preparation

The new capability is supervising a dependency-aware native agent team: complete delegation contracts, accepted handoffs, dependent integration/review, and selective recovery. Earlier source verification, saved instructions and single-assistant tool boundaries remain prerequisites, not new objectives.

Use the fictional CS-2 packet only. No class result authorizes movement. The course is ungraded; technical work checks can return PASS/HOLD, but no learner scores or qualification decision are required.

Allow 90–150 minutes as an unmeasured planning estimate. Confirm the ordinary-user setup: Python 3.12+, latest stable OMP (observed `omp/<semver>` recorded at runtime), current-process OpenRouter key, pinned `anthropic/claude-sonnet-4.6`, external fresh work/evidence paths. Inspect reports release policy `latest`; actual run preflight records the observed identity and rejects a malformed or unsuccessful `--version` or missing key. No provider substitution or implicit retry.

## Observe the operator's decisions

Before dispatch, require a written graph and a complete child brief. The learner rewrites Inventory's Target paragraph and adds a bounded acceptance statement without changing the fixed Input line, return fields or role permissions. The graph must distinguish independent specialists from integration, review and human use.

Ask concrete questions, without supplying a score:

- What does each child receive that makes the assignment executable without the parent conversation?
- Which exact result allows integration to begin?
- Who alone may write the candidate?
- Why can the reviewer not be a fourth item in the first batch?
- What must remain unchanged before an old handoff can be reused?

Do not count a copied graph or a file's existence as the capability. The evidence is the operator's explanation, the actual native dispatch and the decisions made from its results.

## Required native sequence

| Stage | Technical target state | Observable evidence |
|---|---|---|
| Fanout | HOLD, exit 1; Inventory and Authority accepted, Timing blocked | One real native batch, three child sessions, actual ENOENT read of the assigned Timing path, structured blocked yield, no candidate. |
| Repair | PASS, exit 0; only Timing dispatched | Prior seal verified; Inventory/Authority retain original attempt_id and child_id; Timing reads the corrected path in a new child session. |
| Integrate | PASS, exit 0; no child dispatched | Coordinator reads accepted-handoffs and all three sources, then writes only out/status-brief.json; candidate snapshot retained. |
| Review | PASS, exit 0; only Review dispatched | Read-only child receives and actually reads candidate, handoffs and sources before yield; accepted review cites candidate hash. |
| Human decision | Use as status brief, revise or hold | Note outside sealed evidence, identifying candidate and evidence plus remaining responsibility. No real movement authority. |

Run `check --work W --evidence E` after each stage. The expected first HOLD is valid partial evidence, not a malformed execution. A native child can complete successfully with a blocked handoff. Do not confuse that with a denied tool, provider failure or aborted child.

The CLI has exactly `inspect`, `run` and `check`; run stages are `fanout`, `repair`, `integrate`, `review`. Each E is a new path created by the launcher. `--prior` is required after fanout. Review is mandatory, never optional.

## Intervention boundaries

- **Before integration with blocked handoff:** ask which required input is absent; do not allow invented facts or a premature reviewer.
- **All specialists rerun after one correction:** inspect fingerprints and dispatch list. Ask what actually invalidated the other reports.
- **Reused report given a new producing identity:** return to the native chain; names are not unique across attempts.
- **Guard or native evidence missing:** HOLD; a parent summary does not repair provenance.
- **Provider/runtime failure:** preserve partial files, resolve the actual prerequisite, and use a new evidence path. Do not simulate a live outcome.
- **Review findings:** correct producing work and recheck downstream results. Do not edit a reviewer payload or ask for agreement without evidence.
- **Cancellation:** preserve observed return code and partial records; do not claim complete rollback or that every child returned.
- **Learner needs prerequisite help:** repair that prerequisite explicitly, then return to the team boundary. Do not redefine it as the new objective.

## Technical controls and limits

The supplied launcher uses native OMP `task`; it is not a Python scheduler. Its extension is rebound into child sessions, logs actual `ctx.agent` identity and denies tools outside exact context permissions. Read-only children have course_read/yield; integration alone has course_write. No child writer tool is registered for delegated stages. Concurrency is 3 and recursion depth 1. Runtime retry/model fallback are disabled; provider requests are bounded per session and runs have a deadline.

Frozen sources, briefs, roles and controls support selective invalidation. Parent task records, child native sessions, real read outcomes, yields and original identities must agree. `seal.json` detects ordinary evidence changes but is not cryptographic attestation against an operator controlling all files. Tool controls are not an OS sandbox. Do not claim broader deployment security.

Agent Hub and native agent/history/proc URIs are process-scoped. A separately launched TUI cannot observe a headless stage's in-memory team. Interactive supervision is a transfer pattern, not an unobserved claim about this scripted run.

Do not collect credentials, private local files, outside operational details, or model chat history unrelated to the case.
