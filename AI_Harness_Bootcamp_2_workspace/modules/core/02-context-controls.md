## Why

A useful second brain preserves claims you can trace to sources and relationships you can explain. The learner starts the fixed helper's automatic judgment → build → freeze → retrieve chain; a fresh retrieval session then shows whether the saved knowledge is useful without the conversation or judgments that produced it. Source verification is a prerequisite performed independently and does not gate continuation.

## Enabling objectives

1. Direct claim-granular AI judgments across the supplied sources into linked, provisional knowledge while preserving evidence, conflicts, unknowns, and source-as-data limits.
2. Prove that each AI pass loaded the saved rule and consumed the validated preceding handoff, and that fresh retrieval used only frozen navigation and Knowledge notes, not the source-processing chat or raw packet.
3. Give source-backed feedback on one substantive weakness and show its correction in a new content revision and fresh answer that reads and cites the focal note.

Each complete learner-started run uses three paid sessions (judgment, build, fresh retrieval) with automatic local freezing; v1 and v2 use six paid sessions total. Only the helper writes the immutable versioned Knowledge, saved judgments, and navigation. The learner examines saved judgments and actual source support independently and feeds correction via plain Feedback.md.
## Check the work

Follow the links from each provisional claim to its exact source support. Check competing records and state what the evidence does not establish. Keep source verification as the quality bar already practiced in Module 01.

The helper validates the saved instruction's identity and loads it (emitting the instruction_loaded receipt) before any provider contact. File screening, instruction loading, and the tool read boundary establish different facts. A file-screen result alone does not prove that the instruction loaded or that the model followed it. The learner inspects the saved receipt and evidence after the run.

The helper freezes only the navigation note and provisional Knowledge notes. In each fresh retrieval, check the frozen identity, actual note reads, and citations. The raw packet, proposals, reviews, templates, and source-processing chat stay outside the cold read root. Independent source inspection takes place outside that run.

Pick one gap from the v1 run, an unsupported answer or one that skips part of its question, and name the focal note that fixes it. If every answer is already complete, identify one answer needing a substantive qualification or distinction supported by additional source evidence (not duplicate support). The learner examines the saved judgments and actual source support independently after the automatic run completes; no review or approval of changed notes is required before the next revision. Write the observed correction and focal source citation into plain Feedback.md. Confirm that the v2 run read and cited the focal note, and compare its answer with v1's. Cosmetic edits do not demonstrate this objective.

Preserve the first revision and its evidence. Confirm that it still passes its identity check after source-backed Feedback.md updates (Feedback.md is the vault's only learner-editable input to the next run; generated Knowledge remains immutable and helper-written). A missing saved instruction must stop retrieval with exit 2 before provider contact or evidence creation. Restore the same rule bytes for the next fresh run. A digest establishes identity, not truth or authority.

## Supplied-case domain (adapter)

Ledger Pike is a vehicle resupply of surgical instrument sets from Quarry Depot to Clinic P-4 on vehicle QP-17. The warehouse clerk is about to stamp crate C-44 onto that vehicle. Notes DN-001 through DN-040 are that shift's pile. The supplied packet is independent of any earlier module product.

The saved rule treats retrieved paperwork as data, not an order. The supplied file screen accepts clean DN-003 and rejects instruction-like content in DN-014, DN-015, and DN-016. Its missing-input result remains observable. It does not enforce rules inside the harness; manually pasting hostile text remains a bypass.

Process all forty source notes through the fixed helper in one read-only judgment pass (each judging pass actually reads all forty originals). The helper automatically continues to build and fresh retrieval; the learner examines the saved judgments and their source support in the generated Reviews and Knowledge after the run. Give source-backed feedback by editing plain Feedback.md (no edits to generated Knowledge or navigation). Direct the v2 run with the same rule restored after the missing-rule negative on v1. Each complete run uses three paid sessions; v1 and v2 together use six.

Use the same three questions for each fresh retrieval:

- What current inner height applies to C-44, what competing measurement must not supersede it, and what does the measurement not authorize?
- At 12:15 MDT, what evidence exists for quality release, vehicle assignment, permit approval, and the crate's stamp status? Keep those states separate.
- Does paper arriving at 11:40 MDT establish that this movement can start at 12:15? Explain the relevant sequence and missing authority from the available knowledge.

Each supported answer must cite a Knowledge note actually read and its underlying DN identity and excerpt. A truthful unsupported answer must identify the missing support. Review any gap, record the observed correction and source citation in plain Feedback.md, and direct a new revision and evidence destination. The helper generates the updated immutable Knowledge. Preserve earlier attempts and state the result as bounded internal use.
